Extract — integracja APIExtract — API integration

3 / 8

Pobieram trzy źródła osobno. Każde wywołanie ma timeout, sprawdzenie statusu HTTP i log błędu — pipeline nie pada cicho, gdy API nie odpowiada.

I fetch three sources separately. Each call has a timeout, HTTP status check and error log — the pipeline does not fail silently when an API is down.

  • EIA — trzy poziomy: API v2 z kluczem, publiczne arkusze bez klucza (miesięczne RBRTEm/RWTCm i dzienne RBRTEd/RWTCd), a na końcu wartości referencyjne. Poziom, który zadziałał, trafia do kolumny crude_source. Klucz nie jest potrzebny do żadnego ziarna — arkusz dzienny jest nawet świeższy niż miesięczny, bo kończy się na poprzedniej sesji.
  • NBP: GET api.nbp.pl/api/exchangerates/rates/a/{usd,eur}/{start}/{end}/ — okna po 366 dni, bo API ogranicza zapytanie.
  • KE: pobranie XLSX Weekly Oil Bulletin (ceny z podatkiem i bez, Polska).
  • timeout=30 — żądanie nie wisi w nieskończoność.
  • raise_for_status() — kod 4xx/5xx jest błędem, nie pustą tabelą.
  • 404 z NBP to nie awaria — oznacza okno bez dni publikacji (święta), więc zwracam pustą listę.
  • Ponowienia: 2 próby przed zgłoszeniem błędu; log mówi, które źródło i które okno padło.
  • EIA — three tiers: API v2 with a key, public keyless workbooks (monthly RBRTEm/RWTCm and daily RBRTEd/RWTCd), then reference values as a last resort. Whichever tier answered is written to the crude_source column. No key is needed for either grain — the daily workbook is in fact the fresher of the two, since it closes on the previous session.
  • NBP: GET api.nbp.pl/api/exchangerates/rates/a/{usd,eur}/{start}/{end}/ — 366-day windows, since the API caps each query.
  • EC: download Weekly Oil Bulletin XLSX (prices with and without tax, Poland).
  • timeout=30 — the request does not hang forever.
  • raise_for_status() — 4xx/5xx is an error, not an empty table.
  • A 404 from NBP is not a failure — it means a window with no publication days (holidays), so I return an empty list.
  • Retries: 2 attempts before raising; the log names the source and the window that failed.
for attempt in range(retries + 1):
    try:
        response = requests.get(url, timeout=30)
        if response.status_code == 404:      # window with no publication days
            return {"rates": []}
        response.raise_for_status()
        return response.json()
    except requests.RequestException as exc:
        logger.warning("NBP failed (%s %s..%s, attempt %d): %s",

4 / 8

Serie miesięczne łączę po dacie. Z trzech JSON/XLSX powstaje jedna tabela: ropa, kursy, cena na stacji i spread. Kluczowy warunek: obie strony spreadu muszą być w tej samej walucie i tej samej jednostce objętości.

Monthly series are joined on date. Three JSON/XLSX sources become one table: crude, FX, pump price and spread. The key constraint: both sides of the spread must share one currency and one volume unit.

  • JSON / XLSX → pandas DataFrame.
  • Join po miesiącu: Brent + USD/PLN + EUR/PLN + Pb95/diesel.
  • Brent USD/bbl × USD/PLN = Brent PLN/bbl.
  • Brent PLN/bbl ÷ 158,987 l = Brent PLN/l.
  • Pb95 EUR/l × EUR/PLN = Pb95 PLN/l — bez tego kroku spread mieszałby dwie waluty.
  • Spread = Pb95 PLN/l − Brent PLN/l (podatki + marża).
  • Zmiany MoM i YoY liczone na cenie w PLN.
  • JSON / XLSX → pandas DataFrame.
  • Join on month: Brent + USD/PLN + EUR/PLN + Pb95/diesel.
  • Brent USD/bbl × USD/PLN = Brent PLN/bbl.
  • Brent PLN/bbl ÷ 158.987 l = Brent PLN/l.
  • Pb95 EUR/l × EUR/PLN = Pb95 PLN/l — without this step the spread would mix two currencies.
  • Spread = Pb95 PLN/l − Brent PLN/l (taxes + margin).
  • MoM and YoY computed on the PLN price.

Validate — testy jakościValidate — quality tests

5 / 8

Walidacja działa dwupoziomowo: validate() blokuje zapis wewnątrz pipeline'u, a pytest sprawdza gotowy CSV osobno. Testy nie pilnują tylko znaków — pilnują też jednostek i sensu ekonomicznego, bo właśnie tam kryją się błędy, których nie widać po samym uruchomieniu skryptu.

Validation runs at two levels: validate() blocks the load inside the pipeline, and pytest checks the finished CSV separately. The tests do not just guard signs — they guard units and economic plausibility, which is where the errors that survive a clean script run actually hide.

  • Struktura — unikalne daty, jeden wiersz na miesiąc, brak dziur w szeregu.
  • Kursy — USD/PLN w 3,0–5,2, EUR/PLN w 3,5–5,5, implikowany EUR/USD w 0,9–1,35.
  • Jednostki — brent_pln_l musi wynikać z podziału przez 158,987; pb95_pln_l musi być przeliczony kursem EUR, nie USD.
  • Waluty — test_spread_is_same_currency_subtraction to bezpiecznik po realnym błędzie: spread odejmował kiedyś PLN/l od EUR/l.
  • Sens ekonomiczny — spread brutto musi być dodatni i mieścić się w 1,5–6 PLN/l, a spread netto musi być mniejszy od brutto.
  • Pochodzenie — jeśli ropa ma mało unikalnych wartości, znacznik źródła musi to przyznawać.
  • Structure — unique dates, one row per month, no gaps in the series.
  • FX — USD/PLN within 3.0–5.2, EUR/PLN within 3.5–5.5, implied EUR/USD within 0.9–1.35.
  • Units — brent_pln_l must follow from dividing by 158.987; pb95_pln_l must use the EUR rate, not the USD one.
  • Currency — test_spread_is_same_currency_subtraction is a regression guard after a real bug: the spread once subtracted PLN/l from EUR/l.
  • Economic plausibility — the gross spread must be positive and inside 1.5–6 PLN/l, and the net spread must be smaller than the gross one.
  • Provenance — if crude has few distinct values, the source flag must admit it.

def test_spread_is_same_currency_subtraction(df):
    """Regression guard: the gross spread once subtracted PLN/l from EUR/l."""
    both = df.dropna(subset=["pb95_pln_l", "brent_pln_l", "spread_retail_vs_crude"])
    expected = both["pb95_pln_l"] - both["brent_pln_l"]
    assert (both["spread_retail_vs_crude"] - expected).abs().max() < 1e-9

def test_gross_spread_positive(df):
    """Excise plus VAT alone put the pump price well above bare crude cost."""
    assert df["spread_retail_vs_crude"].dropna().gt(0).all()

Load — SQL + CSVLoad — SQL + CSV

6 / 8

Po walidacji zapisuję warstwę analityczną do CSV i SQLite. Zapis jest idempotentny: INSERT … ON CONFLICT(date) DO UPDATE aktualizuje istniejący miesiąc zamiast go duplikować, więc skrypt można uruchamiać cyklicznie (Task Scheduler / cron) bez psucia tabeli.

After validation I write the analytical layer to CSV and SQLite. The load is idempotent: INSERT … ON CONFLICT(date) DO UPDATE refreshes an existing month instead of duplicating it, so the script can run on a schedule (Task Scheduler / cron) without corrupting the table.

  • CSV: data/processed/energy_market.csv — 104 miesiące (2018–2026).
  • SQLite: data/database/energy.db — tabela energy_market, 21 kolumn.
  • Klucz główny: date — jeden wiersz = jeden miesiąc.
  • Świadomie nie używam to_sql(if_exists="replace") — to skasowałoby klucz główny i indeks ze schema.sql.
  • Load porównuje kolumny z PRAGMA table_info i przerywa, jeśli schemat rozjechał się z danymi.
  • CSV: data/processed/energy_market.csv — 104 months (2018–2026).
  • SQLite: data/database/energy.db — energy_market table, 21 columns.
  • Primary key: date — one row = one month.
  • Deliberately not to_sql(if_exists="replace") — that would drop the primary key and index defined in schema.sql.
  • The load diffs columns against PRAGMA table_info and aborts if the schema drifted from the data.

Spread: cena na stacji − ekwiwalent ropy (PLN/l)

Spread: pump price − crude equivalent (PLN/l)

Spread brutto to akcyza, opłata paliwowa, VAT i marża razem — dlatego jest dodatni i liczony w złotówkach, nie groszach. Rośnie, gdy ropa tanieje szybciej niż cena na stacji, i kurczy się, gdy ropa drożeje gwałtownie. Spread netto (bez podatków) jest dostępny tylko dla najnowszej obserwacji z arkusza EC „without taxes" — dlatego pokazuję go jako pojedynczy punkt odniesienia, a nie szereg.

The gross spread bundles excise, fuel levy, VAT and margin — which is why it is positive and measured in zloty, not grosz. It widens when crude falls faster than the pump price and compresses when crude spikes. The net spread (taxes excluded) exists only for the latest observation from the EC "without taxes" sheet, so it is shown as a single reference point rather than a series.

Po loadzie dane siedzą w SQLite (energy_market). Poniższe zapytania odpowiadają na konkretne pytania biznesowe. Pełny plik: sql/queries.sql.

After the load the data lives in SQLite (energy_market). These queries answer concrete business questions. Full file: sql/queries.sql.

1. Ile z ceny Pb95 to ropa, a ile reszta — i jak to się zmienia?

1. How much of the pump price is crude, and how much is the rest — over time?

SELECT date,
       ROUND(brent_pln_l, 2)            AS crude_pln_l,
       ROUND(pb95_pln_l, 2)             AS pump_pln_l,
       ROUND(spread_retail_vs_crude, 2) AS taxes_and_margin,
       ROUND(100.0 * brent_pln_l / pb95_pln_l, 1) AS crude_share_pct
FROM energy_market
WHERE pb95_pln_l IS NOT NULL
ORDER BY date;

Wynik: spread 2,72–5,11 PLN/l (średnio 3,86). W lipcu 2026 ropa to ok. 28% ceny na stacji — reszta to podatki i marża.

Result: spread 2.72–5.11 PLN/l (mean 3.86). In July 2026 crude is about 28% of the pump price — the rest is tax and margin.

2. Czy Pb95 idzie 1:1 za Brent, czy z opóźnieniem?

2. Does Pb95 track Brent 1:1, or with a lag?

WITH base AS (
  SELECT date, brent_usd, pb95_pln_l,
         LAG(brent_usd, 1) OVER (ORDER BY date) AS brent_lag1
  FROM energy_market
  WHERE brent_usd IS NOT NULL AND pb95_pln_l IS NOT NULL
)
SELECT ROUND(
    (AVG(brent_usd * pb95_pln_l) - AVG(brent_usd) * AVG(pb95_pln_l))
    / (MAX(brent_usd) - MIN(brent_usd)), 3
) AS naive_note
FROM base;
-- korelacja liczona w pipeline: 0.77 (nie 1.0)
-- lag 0 wygrywa z lag 1–3 → stacja reaguje w tym samym miesiącu, nie z opóźnieniem

Wynik: korelacja Brent ↔ Pb95 ≈ 0,77. Lag 0 jest najwyższy — cena na stacji reaguje w tym samym miesiącu, ale nie jeden do jednego.

Result: Brent ↔ Pb95 correlation ≈ 0.77. Lag 0 wins — the pump reacts in the same month, but not one-for-one.
